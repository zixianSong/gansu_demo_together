# 产品需求文档（PRD）草案 — 甘肃旅游微信小程序（MVP）

> **文档状态**：草案（基于需求访谈整理）  
> **产品类型**：微信小程序  
> **版本**：MVP（一期）v0.2  
> **更新日期**：2026-09-08

---

## 1. 引言 / 概述（Introduction / Overview）

### 1.1 产品定位

面向来甘肃（及周边）旅行、**已有大概想法但需要灵感与攻略**的游客，提供站内发现与内容阅读能力：通过首页瀑布流、搜索与轮播触达攻略/游记，并在文章中关联到具体地点（景点/线路等）的基础详情，帮助用户把「看了什么」落到「可能去哪」。

### 1.2 长期愿景与本期边界

| 维度 | 说明 |
|------|------|
| **长期愿景** | 帮不会规划的人**快速出行程**，并对行程进行**管理**（含 AI 规划、方案集、行程管理等）。 |
| **MVP 范围** | 只做**发现与内容**：首页发现能力 + 内容详情（含关联地点/线路）+ 搜索与轮播跳转。 |
| **明确二期** | AI 行程规划、方案集、行程管理（含单日时间轴）、公众号真实抓取链路产品化、运营后台、地点/线路自动识别、热门与分类等深度详情与可用入口等。 |

### 1.3 本期实现策略说明

- **前台**：按本 PRD 与现有首页设计实现用户可见能力；行程提示区、AI 悬浮球、分类导航、热门卡片等按现有前端**预留/占位**。  
- **后台**：MVP **不开发运营后台**；文章、地点、轮播等配置数据**直接写入数据库**，用测试数据联调。  
- **公众号抓取**：产品需求上为「运营配置链接 → 系统抓取正文」；本阶段改为**人工写入标题、正文、封面**，真实抓取后置。

## 2. 目标 / 目的（Goals / Objectives）

### 2.1 业务目标（定性）

- 验证「攻略种草 → 关联地点」主路径是否成立。  
- 用可运行的小程序前台 + 测试数据，跑通发现与阅读体验，为二期行程能力打底。

### 2.2 MVP 目标（尽量贴近 SMART）

| 目标 | 说明 | 可衡量性说明 |
|------|------|----------------|
| **S**pecific | 上线可浏览的首页发现 + 文章详情 + 关联地点弹层 + 搜索 + 轮播跳转 | 功能清单见第 5 章 |
| **M**easurable | 成功指标本期暂不设定（已确认延后） | 二期再补 DAU、文章打开率、关联点击率等 |
| **A**chievable | 无运营后台、无真实抓取；依赖库内测试数据 | 降低交付风险 |
| **R**elevant | 对齐核心用户「需要灵感与攻略」；行程能力放二期 | 与愿景不矛盾、分阶段 |
| **T**ime-bound | 以一期排期为准（访谈中未锁定具体上线日） | **待补充上线时间** |

### 2.3 非目标（Out of Scope — MVP）

- AI 表单规划、需求确认弹窗、推荐 3 套行程  
- 方案集、「添加到我的方案集」  
- 行程管理、单日视图、时间轴、首页行程提示真实数据  
- 分类列表/筛选、热门目的地/线路详情页（可点）  
- 地点详情中的交通指南、推荐矩阵、门票预订闭环（除轮播/配置外链外）  
- 运营后台 UI、公众号自动抓取与失败自动下架的完整链路（本期用数据策略模拟）

## 3. 目标受众 / 用户画像（Target Audience / User Personas）

### 3.1 主要用户（MVP）

**有大概想法、需要灵感与攻略的游客**

- 已大致确定方向（如「想去河西」「想看莫高窟周边」），但缺少具体玩法与清单。  
- 习惯刷攻略、游记，希望从内容跳到可行动的地点信息。  
- 本期不要求其完成行程规划或行程管理。

### 3.2 次要角色（内部）

| 角色 | MVP 中的参与方式 |
|------|------------------|
| 运营 / 产品 | 不通过后台操作；通过协作把测试/种子数据写入数据库 |
| 开发 / 测试 | 使用库内数据验证主路径与边界情况 |

### 3.3 暂不作为 MVP 主服务对象

- 完全零想法、强依赖 AI 出行程的用户（二期）  
- 已在旅途中、强依赖「今日行程提醒」的用户（二期）

## 4. 用户故事 / 使用场景（User Stories / Use Cases）

> 以下 6 条已获确认。

1. **作为**有大概想法、需要灵感的游客，**我希望**在首页瀑布流刷到攻略/游记，**以便**快速发现可看的内容。  
2. **作为**上述用户，**我希望**打开一篇文章阅读正文，并能通过页内弹层查看「提及地点/线路」，再进入基础详情（名称、封面、简介、地址），**以便**从攻略落到具体去处。  
3. **作为**上述用户，**我希望**用搜索按关键词查找景点、线路、美食、文章，并在带类型标签的统一列表里点进结果，**以便**按意图精准找内容。  
4. **作为**上述用户，**我希望**点击轮播可到达站内文章、地点详情，或按配置打开网页（web-view）/其他小程序，**以便**看到运营推广的活动或合作服务。  
5. **作为**访客，**我希望**首页仍看到分类导航、热门卡片、行程提示区、AI 悬浮球等布局，但不可用或仅占位，**以便**界面与最终形态一致、后续可平滑上线。  
6. **作为**开发/测试人员，**我希望**文章与地点等数据可直接写入数据库联调（暂无运营后台、暂不接真实公众号抓取），**以便**先验证主路径。

### 4.1 主路径（Happy Path）

```
打开小程序首页
  → 浏览瀑布流（攻略/游记）
  → 进入文章详情阅读正文
  → 点击「提及地点/提及线路」
  → 页内弹层展示关联列表
  → 进入地点基础详情（名称/封面/简介/地址）
```

### 4.2 辅助路径

- 首页搜索 → 统一结果列表（类型标签）→ 文章详情或地点基础详情  
- 首页轮播 → 站内文章 / 地点 / 线路详情，或 web-view 打开 H5（不做其他小程序）

## 5. 功能需求（Functional Requirements）

### 5.1 首页

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| F-HOME-01 | 顶部搜索入口 | P0 | 可发起站内搜索（见 5.3） |
| F-HOME-02 | 轮播图 | P0 | 跳转类型：**站内** `article` / `poi` / `route`；**外链仅** `webview`（H5）。**不支持**跳转其他小程序（`mini_page` 二期）。另可有 `none` 不可点 |
| F-HOME-03 | 分类导航（景区/文博/美食/线路） | P2 占位 | **展示但不可用**；点击统一 Toast「即将上线」 |
| F-HOME-04 | 行程提示卡片区域 | P2 占位 | **功能不做**，按现有前端预留位置；若可点则 Toast「即将上线」 |
| F-HOME-05 | 热门目的地 / 热门线路卡片 | P2 占位 | **仅展示，不可点**（不跳转、不 Toast，或点击无响应） |
| F-HOME-06 | 瀑布流 | P0 | **仅攻略/游记文章**卡片；点击进入文章详情；排序：`published_at DESC, id DESC` |
| F-HOME-07 | AI 悬浮球 | P2 占位 | **功能不做**，按现有前端预留；点击统一 Toast「即将上线」 |

### 5.2 内容详情（文章）

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| F-ART-01 | 文章详情展示 | P0 | 标题、封面、正文等（数据来自数据库人工录入） |
| F-ART-02 | 「提及地点」入口 | P0 | 打开页内弹层，列出关联地点；点击进入地点基础详情 |
| F-ART-03 | 「提及线路」入口 | P0 | 同上，列出关联线路后进基础详情 |
| F-ART-04 | 文章与地点/线路关联 | P0 | **运营侧手动勾选**（本期体现在库表关联数据）；自动识别为二期 |
| F-ART-05 | 无效/不可用内容策略 | P0 | 产品原则：抓取失败或不达标则**不展示/下架**；本期无「不写入或标记下架」的数据策略实现同等效果 |

### 5.3 搜索

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| F-SEARCH-01 | 搜索范围 | P0 | 景点、线路、美食、攻略/文章 |
| F-SEARCH-02 | 结果展示 | P0 | **单一列表**，用类型标签区分 |
| F-SEARCH-03 | 结果跳转 | P0 | 文章 → 文章详情；景点/美食 → POI 基础详情；线路 → 线路模板基础详情 |
| F-SEARCH-04 | 匹配规则 | P0 | 对标题/名称做模糊匹配（`LIKE %keyword%`）；**不搜索正文**；文章仅 `guide`/`travelogue` |

### 5.4 地点 / 线路基础详情

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| F-POI-01 | POI 基础字段 | P0 | 名称、封面、简介、地址（及类型、城市便于展示） |
| F-POI-02 | 适用类型 | P0 | 景点（scenic/museum）、美食（food）统一走 POI 详情 |
| F-ROUTE-01 | 线路模板基础详情 | P0 | 名称、封面、简介；**可展示**副标题与天数（`daysCount`）；无地址则空；**无**加入方案集 |

**明确不做（MVP）**：出行交通指南、景区内推荐矩阵、门票/包车站内下单等。

### 5.5 底部导航

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| F-TAB-01 | 四个 Tab | P0 | 与现有前端一致：首页 / 行程管理 / 服务 / 我的 |
| F-TAB-02 | 非首页 Tab | P2 占位 | 页面可存在；进入后展示占位说明或 Toast「即将上线」，不实现行程/服务深度功能 |

### 5.6 外链与跳转

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| F-LINK-01 | web-view | P0 | 轮播外链**仅**支持 web-view 打开 https H5（体验版/正式环境需配置业务域名；本地开发可先不校验） |
| F-LINK-02 | 其他小程序 | 二期 | MVP **不做** `mini_page` |
| F-LINK-03 | 类型区分 | P0 | 轮播按 `linkType` 分流：站内 `article`/`poi`/`route` + 外链 `webview`（及 `none`） |

### 5.7 数据与「准运营」能力（无后台 UI）

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| F-DATA-01 | 文章种子数据 | P0 | 人工入库：标题、正文、封面、上架状态、关联地点/线路 ID 列表 |
| F-DATA-02 | 地点种子数据 | P0 | 人工入库：类型（景点/线路/美食等）、名称、封面、简介、地址 |
| F-DATA-03 | 轮播配置数据 | P0 | 入库：图片、排序、`linkType`∈{none,article,poi,route,webview} 及对应 linkId/linkPath |
| F-DATA-04 | 真实公众号抓取 | 二期 | 配置链接 → 抓取 → 失败自动下架 |
| F-DATA-05 | 运营后台 | 二期 | 配置链接、关联、上下架、轮播、资料维护等 |

## 6. 非功能需求（Non-Functional Requirements）

| 类别 | 要求 |
|------|------|
| **性能** | 首页首屏与瀑布流首屏在常规网络下可接受加载；列表建议分页或等价懒加载（具体阈值待技术评估） |
| **可用性** | 占位统一 Toast「即将上线」；空搜索、无关联、列表为空时有明确空态（详见 `API-MVP.md` 空态约定） |
| **安全 / 合规** | web-view 业务域名在上体验版/正式前配置即可；MVP 无其他小程序跳转；测试数据勿含未授权隐私 |
| **内容质量** | 仅上架可用正文的文章；损坏内容不对 C 端展示 |
| **可维护性** | 跳转类型、实体类型用枚举/字典，便于二期接后台与抓取 |
| **兼容性** | 以当前项目基础库与微信开发者工具环境为准（实现阶段再锁定最低版本） |

## 7. 设计考量 / 原型图说明（Design Considerations / Mockups）

### 7.1 设计基准

- 首页视觉与布局以现有 MasterGo 设计稿及当前前端实现为基准（搜索、轮播、导航、热门双卡、瀑布流、AI 球、底部 Tab 等）。  
- 样式冲突时遵循项目《微信小程序设计系统》文档（CSS 变量，避免硬编码）。

### 7.2 MVP 交互差异（相对终态稿）

| 模块 | 终态意图 | MVP 表现 |
|------|----------|----------|
| 分类导航 | 进列表/筛选 | 占位；点击 Toast「即将上线」 |
| 行程提示 | 当日行程摘要 → 行程管理 | 仅占位；可点则 Toast「即将上线」 |
| 热门目的地/线路 | 进详情/模板 | 仅展示不可点 |
| AI 悬浮球 | 行程规划入口 | 仅占位；点击 Toast「即将上线」 |
| 轮播 | 多类型跳转 | 站内 article/poi/route + 外链 webview |
| 文章关联 | 弹层 → 详情 | **实现** |
| 搜索 | 全站检索 | **实现**（模糊匹配标题/名称） |

### 7.3 关键页面（建议）

1. 首页（含占位态）  
2. 搜索结果页  
3. 文章详情页（含提及地点/线路弹层）  
4. 地点基础详情页  
5. web-view 容器页  
6. 行程管理 / 服务 / 我的（占位页）

## 9. 待解决问题 / 未来规划（Open Questions / Future Considerations）

### 9.1 原待确认项 — 已拍板（MVP）

| 原问题 | 结论 |
|--------|------|
| 占位模块点击反馈 | **统一** Toast 文案：**「即将上线」**（分类导航、AI 球、行程提示可点区域、非首页 Tab 等） |
| 瀑布流排序 | **`published_at DESC, id DESC`** |
| 搜索匹配规则 | 标题/名称 **模糊匹配**；**不搜正文**；文章仅 guide/travelogue |
| 线路基础详情字段 | 在名称/封面/简介基础上，**允许展示** `subtitle`、`daysCount` |
| 轮播外链 / 小程序 | **外链仅 webview**；站内 **article / poi / route** 可用；**mini_page 二期** |
| web-view 业务域名清单 | **上体验版/正式前再配置**；本地开发可不校验合法域名 |
| 合作小程序 AppId | MVP **不需要** |
| MVP 目标上线时间 | **不阻塞开发**；由排期另行确定（SMART 的 T 暂缓） |
| 种子 SQL 正式文档 | **本期不做**；联调时手工入库或临时 INSERT 即可 |

### 9.2 二期及以后（已识别）

1. **行程能力**：AI 规划全流程、方案集、行程管理与首页行程卡片打通  
2. **内容生产**：公众号链接配置 + 真实抓取 + 失败自动下架  
3. **运营后台**：轮播、文章、关联、地点资料、上下架  
4. **智能关联**：正文自动识别地点/线路 + 人工确认  
5. **发现深化**：分类列表与筛选、热门目的地/线路可点详情（介绍 vs 行程模板）、预订类内容卡片  
6. **成功指标**：量化目标与埋点方案  
7. **跳转其他小程序**（轮播 `mini_page`）  
8. **部署 / 合法域名正式清单**（上云与体验版时补）
