# 产品需求文档（PRD）草案 — 环甘肃游小程序 · 个人中心

> **文档状态**：草案（对话确认后整理）  
> **产品类型**：微信小程序  
> **模块范围**：仅「我的」个人中心及子页  
> **实现深度**：一期按真实能力（登录、支付、核销凭证）  
> **设计依据**：《个人中心.docx》、桌面「个人中心」页面设计  
> **更新日期**：2026-09-18

---

## 1. 引言 / 概述（Introduction / Overview）

### 1.1 模块定位

「我的」是环甘肃游微信小程序的个人中心：用户从底部 Tab 进入后，完成登录、查看与修改基础资料、处理**已经产生的门票订单**、管理足迹 / 评价 / 收藏 / 出行人，提交反馈投诉，阅读隐私与权限说明，并联系客服。

### 1.2 本期边界

| 包含 | 不包含 |
|------|--------|
| 「我的」主页及下述全部子页 | 首页发现、行程管理、景点列表 |
| 已有订单的查询、待支付、去支付、凭证、点评、退款/售后相关操作 | **购票下单**（由其他模块产出订单后，本模块承接） |
| 微信授权登录（头像、昵称） | 登录时采集证件号 |
| 微信客服会话、拨打客服电话 | 完整工单后台（可后置） |

### 1.3 与整站关系

- 底部固定 Tab：**首页**、**行程管理**、**景点**、**我的**；当前高亮「我的」。  
- 订单数据来自购票模块；个人中心不设计下单流程，只处理「已有订单」。  
- 证件号等实名信息在个人主页 **以后再补**，不作为一期登录前置条件。

## 2. 目标 / 目的（Goals / Objectives）

### 2.1 业务目标

让已经或即将使用环甘肃游订票的用户，在一个入口内完成「认出自己、管好订单、补全出行信息、合规知情、找到人帮忙」。

### 2.2 一期目标（尽量贴近 SMART）

| 原则 | 内容 |
|------|------|
| **S**pecific | 上线可登录的「我的」及文档所列子页；订单支持待支付 / 待出行 / 待评价 / 退款售后及对应按钮；支付与凭证走真实能力。 |
| **M**easurable | 见第 8 章成功指标。 |
| **A**chievable | 不写购票；证件号后置；反馈投诉仅简单表单；客服用微信会话 + 电话。 |
| **R**elevant | 服务已有订单的出行用户，补齐交易后半段与账号合规。 |
| **T**ime-bound | 上线日期以项目排期为准（本稿未锁定具体日，见第 9 章）。 |

### 2.3 非目标（一期不做）

- 购票、选场次、选出行人下单  
- 登录或个人主页强制填写证件号  
- 复杂退款审核后台、客服坐席系统  
- 反馈投诉的运营处理台（一期只收表）

## 3. 目标受众 / 用户画像（Target Audience / User Personas）

### 3.1 主要用户

**已产生或将产生门票订单的环甘肃游用户（自由行游客为主）**

- 需要确认订单有没有付清、能不能进园、凭证在哪。  
- 出行后希望点评；下次出行希望少填一次证件和手机号。  
- 关心小程序要了哪些信息和权限。

### 3.2 次要用户

- **未登录游客**：可进入「我的」，看到登录引导；点击需登录的功能时引导授权。  
- **内部客服**：通过微信客服会话或来电处理用户问题（不在本 PRD 做坐席端）。

## 4. 用户故事 / 使用场景（User Stories / Use Cases）

1. 作为游客，我从首页点「我的」，希望一眼看到自己是否已登录，以及订单待办。  
2. 作为未登录用户，我用微信一键授权，希望立刻显示头像和昵称。  
3. 作为已登录用户，我进入个人主页，希望改头像、昵称、性别、生日和签名并保存；手机号、邮箱先只展示。  
4. 作为持有待支付订单的用户，我希望搜索/筛选订单，并完成取消、再次预定或去支付。  
5. 作为待出行用户，我希望打开订单详情，出示核销二维码，并看到出行人（脱敏）和退订规则。  
6. 作为行程已结束的用户，我希望在「待点评」里给场所打分、写感受、传照片/视频并提交。  
7. 作为浏览过甘肃景点的用户，我希望在足迹里按日期看到去过/看过的点，以及浏览数、城市数、旅行天数。  
8. 作为收藏用户，我希望按景点 / 精品线路 / 攻略资讯 / 美食分类查看收藏。  
9. 作为经常出游的人，我希望新增、编辑、删除出行人，并被提醒姓名与证件一致。  
10. 作为不满意的用户，我希望用简单表单提交反馈投诉。  
11. 作为谨慎用户，我希望阅读隐私简要版、个人信息收集清单和应用权限说明。  
12. 作为需要帮助的用户，我希望一键打开微信客服或拨打客服电话。

## 5. 功能需求（Functional Requirements）

> 页面结构、文案与按钮规则以《个人中心.docx》为准；下列为可验收的功能说明。  
> **未登录**访问需登录能力时：引导微信授权，成功后再进入目标页。

### 5.1 「我的」主页

**入口**：底部 Tab「我的」。

**用户信息区**

- 圆形头像、昵称或「点击登录 / 注册」、账号信息、「个人主页」按钮。  
- 未登录：展示登录入口；账号为「未登录」，会员等级为「--」。  
- 已登录：展示微信头像、昵称；账号与会员等级由服务端返回（无等级则显示「普通会员」或「--」，需在实现时与后端约定）。  
- 点击头像/登录文案：未登录则发起微信授权；已登录则进入个人主页。  
- 点击「个人主页」：需登录，进入个人主页。

**我的订单卡片**

- 标题「我的订单」，右侧「全部订单」。  
- 横向四个入口：**待支付**、**待出行**、**待评价**、**退款/售后**。  
- 「全部订单」进入订单列表，Tab 为「全部」。  
- 四个快捷入口进入同一列表页，并选中对应状态 Tab。

**纵向菜单（自上而下）**

| 菜单 | 行为 |
|------|------|
| 我的足迹 | 进入足迹页 |
| 我的评价 | 进入评价页（默认待点评） |
| 我的收藏 | 进入收藏页（默认景点） |
| 我的反馈投诉 | 进入简单表单页 |
| 出行人信息 | 进入出行人列表 |
| 隐私政策简要版 | 进入简要版页 |
| 个人信息收集清单 | 进入收集清单页 |
| 应用权限说明 | 进入权限说明页 |
| 在线客服 | 见 5.14 |
| 关于我们 | 进入关于我们页（产品名、版本、简介） |

**底部 Tab**：首页、行程管理、景点、我的；当前页高亮「我的」。Tab 本身属于整站壳，本模块保证「我的」选中态正确。

### 5.2 个人主页

- 顶栏：返回、标题「个人主页」、右侧更多（一期可仅占位或提供退出登录，见第 9 章）。  
- 头像区：圆形头像；「点击更换头像」（相机入口）；走微信选头像 / 相册或相机（与权限说明一致）。  
- 信息项：  
  - 昵称：可编辑  
  - 性别：选择（如男 / 女 / 保密）  
  - 生日：日期选择  
  - 手机号：仅展示（无则显示未绑定或脱敏号）  
  - 邮箱：仅展示  
  - 个性签名：可编辑多行  
- **证件号本期不采集、不展示。**  
- 底部悬浮「保存修改」：校验后写入服务端并提示成功。

### 5.3 订单列表

- 顶栏：返回；搜索框占位「商品名称/订单号」；筛选；右侧操作图标（一期筛选至少支持按状态，可与 Tab 合并；更多操作为占位则需在实现说明中标明）。  
- Tab：**全部**、**待支付**、**待出行**、**待评价**、**退款/售后**。当前项青色下划线高亮。  
- 支持按标题或订单号搜索，无结果展示「暂无相关订单」。  
- 订单卡片：左上「门票」类型；右上灰色状态；中部标题、有效期、份数、使用方式；右侧灰色价格；底部按钮随状态变化：

| 状态 | 右下角按钮（从左到右） |
|------|------------------------|
| 待支付 | 取消、再次预定、去支付 |
| 待出行 | 取消、再次预定、使用凭证 |
| 待评价 | 点评、再次预定、使用凭证 |
| 退款/售后 | 删除订单、再次预定 |

- 点击卡片空白进入订单详情（按钮点击不误进详情）。  
- 底部「历史订单」提示。  
- **去支付**：调起微信支付，成功后刷新状态。  
- **取消**：二次确认后取消订单（待支付 / 待出行以业务规则为准，失败需说明原因）。  
- **再次预定**：跳转购票模块对应商品（购票流程不在本文展开，需提供跳转约定）。  
- **使用凭证**：进入详情并定位到凭证区，或直接展示凭证。  
- **点评**：进入评价填写页。  
- **删除订单**：仅退款/售后等允许删除的订单，确认后从列表移除（服务端软删或隐藏）。

### 5.4 订单详情

- 顶栏：返回、标题「订单详情」。  
- 大字展示当前状态及一句说明（如待出行：「订单已确认，请按时出行」）。  
- 商品卡片：名称、有效期、份数、使用方式。  
- 出行人卡片：姓名、证件类型、证件号、联系方式，均 **脱敏**。  
- 使用凭证：大尺寸二维码；左右切换多张凭证；已核销次数统计；「使用凭证」按钮（核销以景区扫码 / 服务端状态为准，客户端展示最新核销次数）。  
- 订单信息：可复制订单号；在线支付金额及「费用明细」；交易快照说明；退订规则。  
- 底栏：「取消订单」「再次预订」。

### 5.5 我的足迹

- 顶栏：返回、标题「我的足迹」。  
- 三项橙色统计：浏览景点数、到访城市数、旅行天数。  
- 按日期分组的时间轴：日期分隔、时间点、橙色圆点、景点图、名称、橙色标签、带定位的地址。  
- 数据来自用户真实浏览 / 到访记录（与景点详情等模块打点约定，见第 9 章）。

### 5.6 我的评价

- 顶栏：返回；「待点评」「已点评」Tab。  
- **待点评**：已完成且未评价的订单卡片（类型、待评价、标题、有效期、份数、使用方式、价格、已核销）；按钮：点评（主按钮）、再次预定、使用凭证。无数据时空状态。  
- **已点评**：评分星级与分数、日期、文字、场所名称、「已匿名」及展开/收起。  
- 列表底部「没有更多了」。

### 5.7 写评价

- 从待点评「点评」进入。  
- 场所名称与地址。  
- 五星评分，展示对应标签（如非常满意）。  
- 多行感受输入（需有字数上限，建议 200 字，与现设计一致）。  
- 「照片/视频」上传。  
- 底部「提交评价」：成功后返回评价列表，该单从待点评进入已点评。

### 5.8 我的收藏

- 顶栏：返回、标题「我的收藏」。  
- 横向 Tab：**景点**（默认选中）、**精品线路**、**攻略资讯**、**美食**。  
- 景点：图、名称、起价、收藏日期。  
- 精品线路：图、名称、行程天数与出发地、价格。  
- 攻略资讯：封面、标题、作者、时间、阅读/点赞。  
- 美食：图、名称、评分、人均、位置。  
- 底部「没有更多了」。空分类显示空状态。  
- 点击条目跳转对应详情（景点/线路/攻略/美食详情由其他模块提供）。

### 5.9 出行人信息

- 顶栏：返回、标题「出行人信息」。  
- 「+ 新增出行人」；提示：姓名需与证件保持一致。  
- 卡片：姓名、脱敏证件号、带区号手机号；右侧编辑、删除。  
- 删除需确认。  
- 新增/编辑一期可用表单页或弹层，字段至少：姓名、证件类型、证件号、手机号（提交后脱敏展示）。  
- **个人主页不强制证件号，不等于出行人不能填证件号**——下单核销需要时在本页维护。

### 5.10 我的反馈投诉

- 简单表单：标题、内容、提交。  
- 需登录。提交成功提示，并清空或返回「我的」。  
- 一期不要求用户查看历史工单。

### 5.11 隐私政策简要版

- 返回；浅绿色横幅标题「隐私政策简要版」；副文案「清晰告知提供服务所需收集信息及收集方式」；完整版《隐私政策》链接。  
- 卡片一「为提供服务收集使用的个人信息类型」：账号注册登录；投诉申诉咨询；定位相关功能；拨打联系人电话。底部「查看个人信息收集清单」。  
- 卡片二「为提供服务申请使用的权限」：位置、麦克风、相机、相册。底部「查看应用权限说明」。

### 5.12 应用权限说明

独立页，包含文档第 10 节全部说明文字，以及权限表：

| 系统权限 | 对应业务功能 | 调用权限目的 | 请求权限时机 |
|----------|--------------|--------------|--------------|
| 读写设备存储 | 选择上传或下载文件 | 上传、下载文件 | 使用上传/下载相关功能时 |
| 设备信息 | 安装列表、进程、IMEI、常用设备等 | 关联应用唤起、行为记录、登录设备提醒等 | 启动、第三方登录、分享时 |
| 读取日志文件 | 调试页打印启动时间 | 优化启动时间 | 应用启动时 |
| 麦克风 | 同意并使用录音 | 音视频通话、语音搜索、智能助手 | 使用上述功能时 |
| 剪切板 | 登录、分享 | 复制分享链接、验证码等 | 验证码登录、分享时 |
| 相机 | 更换头像、扫一扫、上传评价 | 实景照片、扫码、评价图 | 使用对应功能时 |
| 相册 | 更换头像、上传评价 | 选取相册照片 | 使用对应功能时 |
| 定位 | LBS、切换城市等 | 自动切换区划、减少选择 | 使用 LBS 相关功能时 |

一期未上线的能力（如扫一扫、语音助手）仍须在文案中按合规清单展示，实际申请权限仅在用户触发对应功能时发生。

### 5.13 个人信息收集清单

独立页。更新日期、生效日期（2026 年 x 月 x 日，上线前填实）。表格：

| 业务场景 | 信息类型 | 收集目的 | 收集方式 |
|----------|----------|----------|----------|
| 账户注册、登录 | 证件类型、证件号、姓名、手机号 | 注册登录认证 | 用户输入 |
| 投诉、申诉、咨询 | 账号、照片、相册图片/视频、沟通记录 | 账号安全、证明材料、咨询与客服质量 | 用户输入、小程序收集 |
| 定位相关功能 | 位置信息 | 精准位置或就近服务 | 小程序收集 |
| 拨打联系人电话 | 设备通话状态 | 编辑与拨号 | 小程序收集 |
| 小程序使用过程 | 页面浏览、功能点击 | 优化体验 | 小程序收集 |

说明：一期登录仅微信头像昵称，证件号后置；清单按合规完整展示「可能收集」的类型，与真实采集节奏以隐私政策正文为准，避免页面承诺与实现不一致（实现时：未采集项不在后台静默收集）。

### 5.14 在线客服

提供两种方式（可操作表或底部双按钮）：

1. **打开微信客服会话**（小程序客服消息）。  
2. **拨打客服电话**（系统拨号，号码由配置提供）。

### 5.15 关于我们

展示产品名称「环甘肃游」、版本号、一两句产品简介；不强制更多品牌物料。

### 5.16 登录与账号（横切）

- 微信授权一键登录，获取头像、昵称并建立用户标识。  
- 不强制手机号授权；若系统已有手机号则个人主页只读展示。  
- 登录态失效时，写操作重新拉起授权。

## 6. 非功能需求（Non-Functional Requirements）

### 6.1 易用性

- 主操作（去支付、使用凭证、提交评价、保存资料）一次可发现，按钮文案与设计稿一致。  
- 空状态、加载中、失败原因用短句说明，避免无反馈。  
- 列表支持基本下拉刷新（订单、评价、收藏、足迹）。

### 6.2 性能

- 「我的」首屏在常规 4G 下尽量 2 秒内可交互（不含超大图）。  
- 订单列表分页或等效限制，避免一次拉全量历史导致卡顿。

### 6.3 安全与隐私

- 证件号、手机号展示脱敏。  
- 支付仅走微信支付；不自存完整银行卡信息。  
- 凭证二维码仅登录用户本人订单可见。  
- 权限按需申请，与权限说明页一致。  
- 传输使用 HTTPS。

### 6.4 可用性与兼容

- 覆盖微信 iOS / Android 近期版本。  
- 弱网：支付与提交给出明确失败，允许重试。  
- 底部安全区（iOS 指示条区域）不遮挡主按钮。

### 6.5 合规

## 8. 成功指标（Success Metrics）

一期以「能力跑通 + 行为可统计」为主，上线后 30 天建议观察：

| 指标 | 建议口径 | 一期参考方向 |
|------|----------|----------------|
| 登录完成率 | 进入「我的」且点击登录的用户中，授权成功占比 | 验证微信登录是否顺畅 |
| 订单待办转化 | 从「我的」进入待支付并支付成功的订单数 | 验证支付闭环 |
| 凭证查看率 | 待出行订单中打开详情或凭证的比例 | 验证出行当天路径 |
| 评价提交量 | 待点评进入并提交成功的条数 | 验证评价闭环 |
| 客服入口使用 | 微信客服会话打开次数 + 拨号次数 | 验证求助是否找得到 |
| 反馈提交量 | 反馈表单成功提交数 | 验证投诉入口 |

具体数值目标（如登录完成率 ≥ 70%）由运营在排期会上拍板后回填。

## 9. 待解决问题 / 未来规划（Open Questions / Future Considerations）

### 9.1 已决定（与 `docs/API-个人中心.md` 1.5–1.7 一致）

- **取消 / 退款**：列表和详情的「取消」只调 `POST /me/orders/{id}/cancel`。待支付 → 已取消；待出行且未核销 → 提交退款申请并进入退款/售后。履约中、已核销不可取消。C 端一期不单独调申请退款接口；不自动打款。  
- **再次预定**：购票未上线时接口 `enabled: false`，前端 toast「购票功能即将上线」，不跳转。上线后门票路径 `/pages/ticket/detail?productId=`。  
- **评价**：默认匿名；媒体走 `POST /me/media` 再提交 URL。  
- **出行人 PUT**：不改证件则不传 `idNumber`；禁止把脱敏串写回。  
- **足迹**：浏览由 `pages/poi/detail`（登录 onShow）写入 `type=1`；到访由核销成功写入 `type=2`。个人中心只读。  
- **收藏**：详情页增删；个人中心只读列表。写入必须带 `extra_info.tab`。  
- **订单列表筛选**：一期 Tab + 搜索即可，「筛选」「更多」占位不做。  
- **删除订单**：`orders.snapshot.userHidden=true`，不改表。

### 9.2 仍待拍板（不挡个人中心联调）

- 一期上线日期与是否分端灰度。  
- 会员等级规则（接口暂固定「普通会员」）。  
- 个人主页「更多」是退出登录还是仅占位（接口已有 logout，产品未指定入口）。  
- 客服电话号码、微信客服是否开通。  
- 隐私政策完整版 HTML / 法务对「登录收集证件号」与一期不采集的表述。

### 9.3 未来规划

- 个人主页补全证件号、手机号绑定、邮箱。  
- 购票模块与个人中心订单状态的完整对账。  
- 退款审核后台、凭证核销对账报表。  
- 反馈投诉工单状态回传给用户。
